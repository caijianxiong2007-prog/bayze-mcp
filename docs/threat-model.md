# Bayze 威胁模型（阶段 0 草案）

范围：P0（MCP stdio、BYOK、无云端组件、无本地监听）。
依据：实施基线规范 v0.3 §8。

## 1. 资产

- A1 API 密钥（用户环境变量）
- A2 用户任务输入与前序模型输出（进程内存）
- A3 本地 journal 摘要与配置文件
- A4 用户预算（供应商计费）

## 2. 信任边界

- B1 MCP 客户端 ↔ Bayze（stdio）：客户端传来的所有内容按不可信输入处理
- B2 Bayze ↔ 供应商 API（HTTPS）：仅允许显式配置的主机；密钥仅在此边界使用
- B3 Bayze ↔ 本地磁盘（配置 / journal）：仅固定路径、受限体积、无密钥

## 3. 威胁与缓解

| # | 威胁 | 跨界 | 缓解（对应基线条目） |
|---|---|---|---|
| T1 | 客户端提示注入：构造 run_workflow 输入诱导越权调用本地能力 | B1 | 工具最小权限（无文件/shell/代理）；`run_if` 封闭枚举、禁任意表达式；输出经 schema 校验；密钥永不进入输出（§7/§8） |
| T2 | 步骤间注入：前序模型输出携带指令攻击下一步 | — | 模板显式分隔并标记不可信；步骤无工具权限；失败项走结构化字段（§7） |
| T3 | `final_output` 注入用户主助理 | B1 出向 | 结果信封标注「模型生成 / 不可信内容」（§4.6） |
| T4 | 密钥经日志 / 错误 / 崩溃报告 / 供应商错误体泄露 | B2/B3 | 统一脱敏层；供应商错误体过滤后记录；验收含伪密钥注入测试（§8/§12） |
| T5 | 供应链投毒（npm 依赖） | — | 直接运行时依赖最小化并锁定；lockfile；`npm audit`；发布前密钥与依赖扫描（§8/ADR-0001） |
| T6 | 本地明文端点或禁用 TLS | B2 | `base_url` 默认仅 HTTPS；本地端点需显式允许并提示风险；`NODE_TLS_REJECT_UNAUTHORIZED=0` 等设置拒绝启动（§8） |
| T7 | DNS rebinding / 系统代理环境变量改变流量路径 | B2 | P0 无 URL 输入工具、端点均为用户显式配置 → 记录为已接受风险；P1 HTTP API 阶段重评（§8） |
| T8 | 资源耗尽（超大输入/输出、并发、慢响应、巨型响应体） | B1/B2 | 输入输出体积、并发 2 / 队列 4、响应体大小、连接/读取超时上限（§3/§8） |
| T9 | journal 无限增长或沉淀敏感内容 | B3 | 仅摘要元数据；7 天 / 10 MB 轮转；`--no-journal`；清除命令（§8） |
| T10 | 预算被计量差异或并发 run 突破 | — | 原子预留 + 实际 usage 结算；未知价格 fail-closed；不承诺零超额（§6） |

## 4. 已接受风险（P0）

- **DNS rebinding 与系统代理环境变量**（T7）：利用前提是用户本地配置或环境已被控制，超出 P0 威胁边界；P1 引入本地 HTTP API 时必须重评。
- **供应商计量差异导致的费用偏差**（T10）：以保守预估与 fail-closed 缓解，不做绝对保证（基线 §5 已如实声明）。
