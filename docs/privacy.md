# Bayze 隐私说明

版本：0.2.0（对应实施基线 v0.4.1 §8 要求逐项说明）

## 一句话总结

Bayze 在你的电脑上运行：你的任务文本只发往**你自己配置的模型服务**（本地 BYOK 直连供应商，或你主动选择的 Bayze 统一 API 经 app.lanwealth.com 转发）；API 密钥只从环境变量读取、只进内存和单次请求头；默认只在本机留一份**运行摘要**（不含任务内容和模型输出），可随时关闭或清除。

## 双接入模式的数据路径（基线 v0.4.1 §8）

| 模式 | 请求路径 | 谁能看到任务内容 | 费用依据 |
|---|---|---|---|
| **本地 BYOK**（默认） | 本机 → 你配置的供应商 API | 仅该供应商 | 供应商账户 |
| **Bayze 统一 API**（可选，用户主动选择） | 本机 → `https://app.lanwealth.com/v1` → 平台转发至实际模型供应商 | Bayze 服务端及其实际调用的模型供应商 | **app.lanwealth.com 账单**（本地估算仅作提示） |

如实声明：Bayze API 模式**不**宣称「请求只在本机处理」或「Bayze 不接触提示词」——该模式下你的任务内容会发送到 Bayze 服务端。两种模式在同一工作流中混用时，每一步的结果都会标明所用模式（`mode: byok | bayze_api`），不存在无提示切换。面向中国大陆用户开放该模式前的合规评估（个人信息跨境、生成式 AI 服务义务等）属独立决策，未完成前不做任何合规承诺。

## 数据流向逐项

| 数据 | 存在于哪里 | 发给谁 | 默认保留 |
|---|---|---|---|
| 任务输入（你让工作流处理的文本） | 进程内存 | 仅发往工作流步骤所配置的供应商（按输入模板裁剪后） | 不落盘 |
| 模型输出 | 进程内存 | 返回给发起调用的 AI 客户端 | 不落盘 |
| API 密钥 | 环境变量 → 进程内存 | 仅作为请求头发往对应供应商端点 | 从不写入配置/日志/journal/仓库 |
| 运行摘要（状态、模型、耗时、用量、费用估计） | 本机 journal 文件（JSONL） | 任何人（不出本机） | 7 天 / 10 MB，自动轮转 |
| 运行日志 | 本机 stderr（已脱敏） | 任何人 | 不落盘 |
| 配置文件 | 本机 OS 用户配置目录（不含密钥） | 任何人 | 直到你删除 |

关键事实：

- **无遥测**：不向 Bayze 或任何第三方发送统计数据；不存在「拨打回家」的代码（网络请求只存在于 `src/providers/common/http.ts`，目标仅为你配置的供应商端点）。
- **无云端组件、无监听端口**：每个 AI 客户端拉起一个独立 stdio 子进程，进程退出即结束。
- **进度通知的内容边界**：AI 客户端收到的进度只含步骤名与状态（如 `step draft: running`），不含任务文本或模型输出。
- **输出信任边界**：`run_workflow` 返回的最终输出标注为 `finalOutputUntrusted: true`——它是模型生成内容，不应被当作指令执行。
- **供应商错误脱敏**：供应商返回的错误体会先脱敏（去除 Bearer/密钥形态的片段）并截断后才进入日志或错误消息。

## 如何清除本机数据

```bash
node dist/src/cli.js journal clear     # 删除全部运行摘要
node dist/src/cli.js journal path      # 查看摘要文件位置（也可直接删除）
# 配置目录同路径下：config.yaml（配置，含供应商与模型清单，不含密钥）
```

启动 server 时加 `--no-journal` 可完全不写运行摘要。

## 会向哪家供应商发送哪些数据

运行 `list_workflows` 可见每个工作流每一步的 provider 与 model；每一步实际发出的内容 = 该步骤输入模板渲染结果（`original` 只含原始任务；`review_template` 含原始任务 + 草稿 + 要求返回 JSON 评审；`revision_template` 含原始任务 + 草稿 + 结构化评审意见）。**绝不**发出：密钥（发给别的供应商）、journal 内容、你的其他会话、内部日志。

## 已接受的限制（如实声明）

- 模型输出本身经过你配置的供应商——请自行评估该供应商的隐私政策。
- 供应商计量差异可能导致费用估计偏差（保守预估 + 未知价格 fail-closed 缓解，不做绝对保证）。
